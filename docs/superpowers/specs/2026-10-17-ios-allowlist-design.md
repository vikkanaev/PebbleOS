# Белый список iOS-уведомлений и звонков в PebbleOS (маркер `@allow`)

Дата: 2026-10-17. Часы: Pebble Time 2 (плата `obelix`, платформа emery). Телефон: iPhone.
Репозиторий: форк `coredevices/PebbleOS`, ветка `ios-allowlist`.

## 1. Цель

На iPhone получать на часы:

- звонки только от контактов из белого списка;
- уведомления о сообщениях только из Telegram и только от белого списка;
- ничего другого.

Список должен редактироваться с телефона без перепрошивки. Мобильное приложение Pebble для iOS не пересобираем.

## 2. Контекст: как это работает сегодня

- На iOS уведомления и звонки приходят в часы напрямую по ANCS, минуя приложение Pebble. Фильтрация возможна только в прошивке.
- Стоковая прошивка (PR coredevices/PebbleOS#1161, май 2026) поддерживает «iOS Notification Filter Rules»: на приложение список правил `contains` по Title или Body с флагом регистра. Правила задаются в стоковом iOS-приложении Pebble и синхронизируются в часы через BlobDB (`ios_notif_pref_db`, атрибут `AttributeIdNotificationFilteringRules`).
- Семантика сегодня только блок-лист: совпало правило, уведомление отброшено (`ancs_filtering_matches_rules` в `fw/services/notifications/ancs/ancs_filtering.c`, вызов в `prv_should_ignore_notification` в `ancs_notifications.c`).
- Проверка правил выполняется в `ancs_notifications_handle_message` **до** ветки входящего звонка, поэтому правила приложения Phone применяются и к звонкам. Title входящего звонка это имя контакта либо сырой номер.
- Regex в прошивке не реализован: правило типа Regex всегда возвращает «не совпало».

## 3. Решение

Добавить в прошивку соглашение: если среди правил приложения есть правило-маркер `@allow`, остальные правила этого приложения трактуются как белый список.

### 3.1. Маркер

- Правило считается маркером, если его `pattern` после обрезки пробелов по краям равен `@allow` без учёта регистра (ASCII-сравнение).
- `match_type`, `match_field`, `case_sensitive` у маркера игнорируются.
- Маркер никогда не участвует в матчинге содержимого.

### 3.2. Семантика

| Состояние правил приложения | Результат |
|---|---|
| Правил нет | Пропустить (стоковое поведение) |
| Есть правила, маркера нет | Блок-лист: отбросить, если совпало хотя бы одно правило (стоковое поведение) |
| Есть маркер и другие правила | Белый список: пропустить, если совпало хотя бы одно не-маркерное правило, иначе отбросить |
| Только маркер | Отбросить всё (пустой белый список) |

Regex-правила в белом списке никогда не совпадают, то есть никого не пропускают. Это ожидаемо, пока regex не реализован в прошивке.

### 3.3. Матчинг содержимого

Не меняется: байтовый `contains` по UTF-8, нечувствительность к регистру только для ASCII, правило с полем Title проверяет title и subtitle, поле Body проверяет body, поле Any проверяет всё.

Следствия для пользователя:

- кириллические имена писать ровно как в Контактах iOS;
- белый список звонков по именам контактов, не по номерам (номер в title приходит с форматированием);
- для Telegram в личке title это имя отправителя, в группах имя группы;
- правила белого списка задавать с полем Title, чтобы имя внутри текста чужого сообщения не пропускало его.

### 3.4. Изменения в коде

`fw/services/notifications/ancs/ancs_filtering.c`:

- вынести разбор сериализованного списка правил в один проход, который возвращает признак наличия маркера и результат матчинга не-маркерных правил;
- добавить публичную функцию
  `bool ancs_filtering_should_ignore_by_rules(const iOSNotifPrefs *prefs, const ANCSAttribute *title, const ANCSAttribute *subtitle, const ANCSAttribute *body)`,
  реализующую таблицу из 3.2;
- `ancs_filtering_matches_rules` сделать внутренней (`static`) или удалить, если других вызовов нет.

`include/pbl/services/notifications/ancs/ancs_filtering.h`: объявить новую функцию, убрать старую из публичного API.

`fw/services/notifications/ancs/ancs_notifications.c`, `prv_should_ignore_notification`: заменить вызов на `ancs_filtering_should_ignore_by_rules`. Лог на уровне DBG с причиной: `Matched block rule` либо `No allow rule matched`.

Не трогаем: формат сериализации правил, BlobDB, протокол, мобильное приложение, обработку звонков (`ancs_phone_call.c`), Quiet Time, Mute.

### 3.5. Что не делаем (YAGNI)

- Отдельный UI на часах.
- Новый байт `mode` в протоколе и правки iOS-приложения. Это возможная вторая фаза для upstream (issue coredevices/PebbleOS#2088).
- Regex в прошивке.
- Нормализацию номеров телефонов.

## 4. Тесты

Юнит-тесты в `tests/fw/services/notifications/test_ancs_filtering.c`, по образцу `test_ancs_filtering__matches_text_rule_body_case_insensitive` и helper `prv_set_rules`:

1. Без маркера, правило совпало: отбросить (регресс стокового поведения).
2. Без маркера, правило не совпало: пропустить.
3. Маркер + правило Title совпало: пропустить.
4. Маркер + правило Title не совпало: отбросить.
5. Только маркер: отбросить.
6. Маркер записан как ` @ALLOW ` (регистр, пробелы): распознан.
7. Маркер с полем Body и флагом регистра: распознан, остальные флаги проигнорированы.
8. Маркер + regex-правило: отбросить (regex не совпадает).
9. Правил нет: пропустить.

Тест в `test_ancs_notifications.c` на то, что входящий звонок с title вне белого списка Phone не доходит до `ancs_phone_call_handle_incoming`, если существующие стабы это позволяют. Иначе проверка руками на часах.

Запуск: `pbl test` по `docs/development/tests/unit.md`.

Сквозная проверка на часах: звонок с контакта из списка (часы звонят) и не из списка (молчат); сообщение в Telegram от человека из списка (пришло) и не из списка (нет).

## 5. Сборка, прошивка, сопровождение

Окружение на macOS по https://pebbleos.readthedocs.io/en/latest/getting_started/index.html:

```bash
brew install python git openocd && brew link python@3
gh repo fork coredevices/PebbleOS --clone --default-branch-only ~/projects/Peble/PebbleOS
cd ~/projects/Peble/PebbleOS && git submodule update --init --recursive
brew install $(cat requirements-brew.txt)
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
curl -LsSf https://github.com/coredevices/PebbleOS-SDK/releases/latest/download/pebbleos-sdk-installer.sh | sh
git checkout -b ios-allowlist
```

Сборка и прошивка:

```bash
pbl configure --board obelix -DCONFIG_RELEASE=y
pbl build
pbl bundle            # .pbz в build/
```

`.pbz` на iPhone, в приложении Pebble: Settings → Show debug options → Devices → часы → Firmware Update Debug → Sideload FW.

Откат: Back+Up+Select перезагружает в PRF, оттуда приложение ставит стоковую прошивку.

Сопровождение: на каждый релиз upstream rebase ветки на тег, пересборка, sideload. Предложения приложения обновиться на стоковую прошивку игнорировать. Коммиты с DCO sign-off (`git commit -s`) по `CONTRIBUTING.md`, чтобы ветку можно было превратить в PR.

## 6. Настройка на iPhone

1. Pebble → Notifications: всем приложениям, кроме Telegram и Phone, поставить Mute.
2. Telegram → Filter rules: добавить `@allow`, затем по правилу на имя, поле Title.
3. Phone появляется в списке после первого входящего звонка на прошитых часах. Правила те же.
4. Побочный эффект: уведомления о пропущенных звонках от людей вне списка тоже не приходят.
5. Лимит: добавлять `@allow` ПЕРВЫМ правилом и держать список коротким: прошивка хранит не более 512 байт правил на приложение (примерно 20-25 коротких имён); при обрезке хвост списка теряется, а в логах часов появится предупреждение "Filter rules truncated".

## 7. Риски

- Формат правил на стороне приложения может измениться в будущих версиях, тогда маркер перестанет доезжать. Признак: правила в приложении есть, фильтр не работает. Проверять после обновлений приложения.
- Кастомная прошивка не получает автообновлений, нужна ручная пересборка.
- iOS может подставлять в title звонка не имя, а номер, если контакт не распознан (например, формат номера). Тогда звонок будет отброшен. Решение: привести номер контакта к формату, который iOS распознаёт.
- Обрезка правил: добавлять `@allow` ПЕРВЫМ правилом и держать список коротким: прошивка хранит не более 512 байт правил на приложение (примерно 20-25 коротких имён); при обрезке хвост списка теряется, а в логах часов появится предупреждение "Filter rules truncated". Если `@allow` окажется за границей обрезки, список превратится в блок-лист.
